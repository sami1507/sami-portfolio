# دليل تشغيل بورتفوليو سامي أبو رائد

موقع مبني باستخدام Next.js وTypeScript بأربع لغات: الإنجليزية افتراضيًا في `/`، والعربية في `/ar/`، والعبرية في `/he/`، والألمانية في `/de/`. العربية والعبرية تدعمان RTL. تبقى الإنجليزية لغة الرابط الرئيسي مهما كانت لغة المتصفح، ويحافظ مبدّل اللغات على صفحة المشروع الحالية. يعمل الموقع كتصدير ثابت دون قاعدة بيانات أو خدمة خلفية.

## التشغيل من نسخة جديدة

ثبّت Node.js 24، ثم افتح الطرفية داخل مجلد `portfolio`:

```sh
npm ci
npm run dev
```

افتح <http://127.0.0.1:3000>. لبناء نسخة الإنتاج وتشغيلها محليًا:

```sh
npm run build
npm start
```

ينتج البناء مجلد `out`، ويقدّم أمر `start` ملفاته عبر خادم محلي بسيط.

## تعديل المحتوى

- `src/data/site.ts`: الاسم، وروابط التواصل، والسيرة، ونصوص الواجهة باللغات الأربع.
- `src/data/interface.ts`: أوصاف الصور، والتنقل، ومعرض الشاشات، ورسائل الخطأ، وبيانات صفحات البحث باللغات الأربع.
- `src/data/projects.ts`: بيانات المشاريع ودراسات الحالة، والأدوار، والتقنيات، وروابط المصدر والتجربة، والأدلة.
- `public/images`: صور المشاريع. استخدم صورًا فعلية مع نص بديل دقيق، وحافظ على أبعادها وتحسين حجمها.

لإضافة مشروع، أضف عنصرًا إلى مصفوفة `projects` بمعرّف `slug` فريد ونصوص باللغات الأربع (`en` و`ar` و`he` و`de`). يوجّه النوع `Project` الحقول المطلوبة. اختر نوع عرض متاحًا أو أضف تكوينًا بصريًا في `src/components/ProjectVisual.tsx`، ثم أعد البناء لتوليد صفحات المشروع.

الأدوار المؤكدة من سامي: **PATHY مشروع أكاديمي لشخصين ببرمجة مشتركة؛ TravelScan AI مشروع أكاديمي فردي؛ TaskFlow مشروع شخصي فردي**. حافظ على هذا التمييز عند تحديث النصوص، وأضف نتائج أو قياسات فقط عند وجود دليل عليها. راجع `CONTENT-SOURCES.md` لمصادر المحتوى.

## إضافة السيرة الحقيقية

ضع ملف السيرة الفعلي مثلًا في `public/sami-abu-raaed-resume.pdf`، ثم غيّر `profile.resume` في `src/data/site.ts` من `null` إلى:

```ts
resume: "/sami-abu-raaed-resume.pdf",
```

يبقى رابط السيرة مخفيًا ما دامت القيمة `null`. افتح الملف من الموقع بعد البناء للتأكد من صحة الرابط.

## النشر

اضبط `NEXT_PUBLIC_SITE_URL` على عنوان الموقع النهائي الكامل **قبل البناء**، دون مسار فرعي، مثل `https://your-domain.example`. تعتمد الروابط الأساسية وخريطة الموقع على هذا العنوان. يمكن وضع المتغير في ملف `.env.local` محلي غير مرفوع إلى المستودع، أو في إعدادات بيئة الاستضافة.

شغّل `npm run build` وانشر محتويات `out` لدى استضافة تدعم المواقع الثابتة. اضبط مجلد المشروع على `portfolio` ومجلد المخرجات على `out` إن كانت الاستضافة تبني المستودع مباشرة. اختبر الصفحة الرئيسية و`/ar/` و`/he/` و`/de/` وصفحات المشاريع والروابط بعد النشر. وجود إعدادات النشر أو عنوان داخل الكود لا يعني اكتمال النشر؛ اعتمد على نتيجة عملية النشر الفعلية.

## الفحوص

```sh
npm run typecheck
npm run test:e2e
npm run audit
```

راجع `README.md` لتفاصيل تجهيز المتصفح وأوامر الفحص. تحتاج مراجعة الأداء إلى نسخة إنتاج محلية قيد التشغيل. النتائج المقاسة وظروفها وحدودها موجودة في `QA-REPORT.md`؛ لا تُستنتج نتيجة Lighthouse من نجاح البناء وحده.

## ملاحظة خاصة بالجهاز الحالي

المصدر الأساسي القابل للتعديل موجود في:

```text
C:\Users\User\OneDrive\Desktop\pathy\PATHY\PATHY\portfolio
```

بسبب امتلاء قرص C سابقًا، استُخدم `D:/sami-portfolio-20261107` لنسخة البناء وملفات الاعتماد والمخرجات، مع روابط محلية لبعض مجلدات العمل. **عدّل المصدر الأساسي في C**؛ نسخة D مخصّصة للبناء وليست مصدرًا مستقلًا للمحتوى. عند البناء عبر نسخة D، زامن ملفات المصدر إليها أولًا، ثم أعد المخرجات إلى موقع المعاينة عند الحاجة. لا تنقل روابط المجلدات الخاصة بهذا الجهاز إلى جهاز آخر.

النسخة الجديدة العادية لا تحتاج إلى قرص D أو هذه الروابط: تكفي خطوات `npm ci` ثم التشغيل أو البناء في مجلد المشروع.
